# Agent 0.5.15：按问题取数与服务式反馈

## 这次修正的根因

用户提供的中断对话问的是整个作品集的日内浏览、收藏、点赞分布。导出中有 15 条来源，其中 9 次是单篇历史分页，共 450 行；来源结果合计 76,038 个 UTF-8 字节。路径经过总览、质量、头部作品、分析简报和增长排名，却没有直接计算全作品的日内增量分布。只压缩这些结果，仍然是在压缩未能回答问题的数据。

前一版还把每次调用完成、来源复用自动变成公开小结。这是执行日志，不是用户需要的分析反馈。提供的导出只有问题、空的最终回答和中断状态，不能据此评价未保存的阶段文本，也不足以重建用户的完整原始数据库。本次不把导出中的私有作品内容复制进代码或测试。

## 通用工作流

1. 根据最近的用户问题识别分析维度，简短追问继承前文维度，明确换题时切换方向。该识别只是初始工具选择提示，不代替模型理解或替用户猜测日期、范围与指标。
2. 时段、排名、比较、数据质量分别提供相关工具；这些问题不再默认预读总览。正文与通用问题保留较广的能力范围。模型先说明正在核对的用户问题，再直接查询相关聚合。
3. 时段分布由本地工具一次计算全体所选作品的多个指标。其余问题分别使用全库排名、分组、作品比较、增长和质量查询，避免固定的“总览—排名—质量—历史”清单。
4. 明细工具可通过 `request_analysis_tools` 展开。需要说清尚未解决的问题、已有结果为什么不足；它返回所需工具的完整参数定义，供下一轮使用。用户明确要求原始记录时直接提供明细。该机制没有请求次数、输入、输出或累计 token 配额，也不改变已有数据及正文授权。
5. 每次追加取数用于解决具体缺口；已经覆盖问题就回答。长任务继续使用来源笔记、稳定引用、无损编码和原始证据回查。不会为了停止消耗而静默丢弃用户问题或截断回答。

关键词识别不可能覆盖全部自然语言表达，模型可以通过工具发现修正初始选择。公开说明和语义层面的完成判断仍依赖模型；确定性工具与测试不能证明所有模型都会做出最优决策。

## 时段统计的口径

`analyze_time_patterns` 支持日内时段、星期和逐日变化，可选择全部或部分作品，同时计算浏览、收藏、点赞和评论。一次建立本地观测索引，模型只收到聚合结果。

- 计算连续有效观测之间的指标差额，不把作品初始累计值当作新增；保留回落与负值。
- 合并改变样本、确认未变化的观测及观测批次。缺失了对应样本的“发生变化”记录会断开连续性，不能用先前值补零。
- 空值表示未观测，零表示确实没有净变化。单个指标缺失不会让其他可计算指标丢失。
- 按北京时间分组，将区间增量归入结束时段；恰好落在边界时归入前一时段。跨时段的归属是近似，不进行均匀插值，也不能当作事件发生时间。
- 超过目标时段宽度 10% 的采样间隔、或压缩粒度比时段更粗的样本，不参与该粒度的峰谷判断。返回被排除的增量、边界区间、缺测和跨时段数量，并建议更宽的时段；需要 24 小时时转为逐日比较。日级也可能仍然不足，不能强行推断小时峰谷。
- 同时返回净增量、正／负差额、正增量占比、每个观测作品小时的变化率、覆盖天数和作品数。峰谷按该归一化速率比较，避免把采样次数更多直接解释为活跃度更高；它不是整个账号每小时的事件数，作品构成差异仍可能影响比较。
- 摘要覆盖全部结果，日历分页不会把当前页冒充完整区间。输出明确保留观察口径和限制；历史相关性不能证明最佳发布时间或因果。
- 缓存指纹包含独立观测与观测批次，只有覆盖变化时也会失效。分析不修改原始数据或数据保留策略。

## 用户能看到的反馈

发送后立即显示正在分析的方向。模型在分析有实质进展时输出一句用户相关的说明，例如：“部分采样间隔超过一小时，我会再按更宽的时段比较，避免把缺测误判为低谷。”

应用不再为每次工具完成生成自动段落。工具名称、缓存、来源内容、队列、请求数和用量默认放在“执行详情”中；收起详情不会隐藏公开反馈。旧历史中的自动 `milestone:` 段落也不再展示为公开分析。公开反馈与最终回答分别保存，导出现在包含公开反馈和实际用量，便于再次排查。

每次进入 Agent 默认新对话，历史需主动选择；切换视图不停止后台生成，完成后也不会抢回当前选择。

## 验证证据

- 全部 71 个测试文件、536 项测试通过，类型检查通过。全套图表测试仍有 JSDOM 不实现 Canvas 的环境提示。
- 使用用户原问题复现旧首轮工具集缺少时段聚合的问题；增加自然语言变体、短追问、换题、原始明细请求和多分析方向回归。
- Responses 与 Chat 两种实际 SDK 路径验证：相关工具选择 → 全作品多指标聚合 → 公开发现 → 最终回答；另验证发现具体疑点后展开并成功调用明细工具。没有自动工具小结。协议响应由确定性夹具提供。
- 时区边界、全范围摘要、采样疏密、负值、新作品、缺测、零变化、粗粒度样本与观测批次的回归通过。
- `node scripts/agent-workflow-benchmark.mjs` 使用 38 篇合成作品、15,200 条十五分钟采样：24 个结果时段，三个指标的证据报文 6,060 字节；完整工具说明 8,658 字节，聚焦后的说明（包括展开工具）5,371 字节；本次本地索引及计算约 110 毫秒。
- 生产 ZIP 和已安装目录构建校验通过，版本均为 0.5.15；浏览器以生产 bundle 连接本机确定性 SSE 服务，确认公开句子在生成结束前逐步出现、默认无工具／缓存流水账、详情可展开且不影响反馈、后台完成和切回／刷新默认新对话。

上述合成测量不是用户原数据的前后 A/B，也不是 token 账单降幅。没有使用私人 API key 重跑真实模型长分析；真实模型的取数选择、最终答案质量和成本仍需要用同一问题、数据和配置实测。原有预算移除回归继续通过。
