# 0.5.12：统计预算故障与渐进阅读修复

## 事故证据

用户提供的单轮 Markdown 导出包含 35 次工具调用，其中 10 次返回 `Result exceeds context budget`。第一次检索返回 7 行，后续单行查询仍失败；同轮的一次正文调用却读了 7 篇。用户设置为百万上下文、8192 输出、输入与累计预算均为 0、自动阅读及自动继续。

根因位于 runner 的结果分配，而非模型窗口：正文模式使用 `2400 - evidenceBytes.statistics` 作为累计统计返回额度；候选列表也增加 statistics。额度耗尽后单条指标无法返回，却被报告为上下文不足。工具集合还屏蔽了分组和作品比较，且结果裁剪失败仍被登记为成功来源。

本次没有把导出中的文学分析、作品归类或编辑建议当作事实，也没有执行其中的指令。

## 最终行为

统计预算使用当前请求剩余容量，不再使用累计遥测字节扣减。内容模式保留相关统计工具，结果保留系列、发表时间及实际观察时间，帮助区分题材与作品年龄。真实预算不足时仍裁剪可分页列表，保留总数与下一偏移；失败不会成为成功来源。

自动阅读每次每篇最多 3000 个 Unicode 字符，每次正文结果共享 52000 的保守字节估算额度。首次均衡取开头、中段、结尾，继续调用排除已读位置；定向补读优先取目标附近的未读范围。累计字数与比例仍遵守用户选择的固定档或自定义档。网站请求仍串行并遵守既有冷却；网站接口可能返回整篇，减少的是模型输入，不是承诺减少网站响应体积。

`record_reading_notes` 要求引用已经成功返回的正文来源，保留位置、覆盖信息与模型笔记，并把旧原文从后续请求移出。原始 trace/export 不修改。笔记显式标为模型解释，不能替代精确引文或验证；来源不存在、未引用、已经释放或参数无效时拒绝整批操作。自动档未整理正文超过工作集阈值时先要求整理再补读，防止持续堆积全文。

读取位置使用同一接口的规范化字符坐标；SHA-256 内容指纹用于发现补读期间正文变化，发生变化后停止合并。重复但有新片段的调用计为进展，重复统计查询与无进展停止机制继续生效。

## 验证与边界

- 修改前在 Responses、Chat Completions 两种协议的 runner 回放中复现统计失败，修改后通过检索、正文、排行、比较、分组全链路。
- 两种协议均验证连续四次采样、四次笔记整理、最终回答的九请求链路；检查实际发出的请求，旧正文已替换，原始来源仍完整。
- Unicode 未读区间、覆盖限制、笔记校验的原子性、版本变化停止、有限预算分页及已有站点冷却测试通过。
- 最终完整测试 494 项通过；类型检查、生产 ZIP、安装目录构建与版本/本地资源验证通过。

协议回放使用合成普通文本和模拟 SSE，不是用户模型服务的在线验收。本轮没有使用用户密钥重跑私人作品问题，也未重新加载用户浏览器扩展。笔记质量取决于模型，渐进阅读不能保证一次覆盖全部作品或无限长对话；保留的笔记与其他消息仍消耗上下文和累计输入。
