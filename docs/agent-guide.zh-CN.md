# Agent 使用指南

[返回项目首页](../README.md) · [构建与排错教程](./agent-building-tutorial.zh-CN.md)

Agent 是可选功能。图表、作品库、比较、同步与备份无需接入模型；使用 Agent 时，对话会发送至你配置的模型服务。

## 连接模型

1. 打开完整看板中的 **Agent 分析 → 连接配置**。
2. 填写 Base URL、API 协议、模型名称和 API key。不要把 Pixiv 的 Cookie 填入密钥栏。
3. 按需要开启“允许 Agent 查询本地作品和历史数据”。不开启时仍可普通对话。
4. 点击“测试连接与工具调用”。这会向模型服务发送测试请求，验证工具调用及回传，不发送作品数据。
5. 保存配置，返回对话并提问。

当前代码的初始预填如下。这些是应用配置，不是对服务商模型规格、可用性或价格的保证；请按所选模型实际能力修改。

| 字段 | 初始值 |
| --- | --- |
| Base URL | `https://api.deepseek.com` |
| API 协议 | Responses API |
| 模型名称 | `deepseek-v4-flash` |
| 数据分享 / 正文采样 | 均关闭 |
| 记住 API key | 关闭 |

支持自定义 Responses 或 Chat Completions 兼容服务。远程服务使用 HTTPS，本机 HTTP 服务可不填 key。模型列表获取失败时可手动填写名称。应用不发送 `max_tokens`、`max_completion_tokens` 或 `max_output_tokens`，由服务商采用自身默认生成上限。

保存或测试时仅申请所选 API 域名的可选权限。接口协议不兼容、没有相应模型或密钥无效时，需要调整配置；单纯获取模型列表成功不代表工具调用可用。

## 从统计问题开始

开启数据分享后，Agent 可使用本地聚合工具查询概览、作品、历史、排行、转化率、比较、粉丝及数据质量。排行由本地数据计算，按问题发送所需结果，不需要先把全部历史交给模型。

推荐先问具体、可核对的问题：

- “最近 7 天浏览增长前五的作品是什么？哪些样本不足？”
- “比较这三件作品的收藏率与近期收藏增量。”
- “今天的变化与近 24 小时为什么不同？”

展开回答的来源，核对作品名称、时间范围和原始结果。来源编号表示引用的查询证据，不意味着模型推断一定正确。

## 小说正文分析

正文采样需要同时开启数据分享和“允许按需采样 Pixiv 小说原文”。统计分析不需要这项权限。

Agent 可先选择候选作品，再按问题读取开头、中段、结尾、均衡片段或关键词附近内容。渐进阅读优先复用片段缓存，否则使用当前 Pixiv 登录态请求同一小说正文接口，以保持补读位置一致，不自动新建小说标签页。

| 深度 | 每问每篇的采样限制 |
| --- | --- |
| 自动 | 每次每篇最多约 3,000 字符，各篇独立采样；按需补读未读位置，每问不设固定累计字数或比例上限。 |
| 轻量 | 最多 1,500 字、30%。 |
| 标准 | 最多 3,000 字、50%。 |
| 深入 | 最多 6,000 字、70%。 |
| 自定义 | 自行设置字数及 1–100% 比例。 |

固定档同时受字数和比例约束；实际内容还受正文可访问范围与模型上下文限制。没有固定三篇配额，可按问题读取多篇。过程记录展示实际作品、排队、请求间隔、读取结果和覆盖率。

“自动 / 正文优先 / 指标优先”决定分析侧重。正文优先减少无关统计证据，但保留分组、比较与增长查询能力；不会把题目、标签或标题当作读过全文的证明。

覆盖率仅针对已加载正文，不保证多页作品或完整系列覆盖。模型不具备此扩展提供的图片理解能力；片段分析也不能替代通读。登录、访问权限、限流或页面变化导致失败时会明确说明，不绕过站点限制。

## 高效分析与运行过程

从 0.5.14 起，彻底移除应用层的单次输入、累计输入、输出预算以及本地上下文窗口拦截。不再裁剪历史问题或因字节估算提前关闭工具。旧配置中的预算字段自动忽略，保存时移除；模型地址、密钥、数据授权、阅读偏好保留。

0.5.15 进一步调整通用取数流程：先识别问题要比较的对象、指标、时间维度，再提供相关工具；时段、排名、比较和数据质量各自直接进入对应查询。遇到具体疑点可按需展开其余已授权工具，明确要求原始明细时直接提供明细工具。没有新增调用或 token 配额。

减少消耗依靠数据组织：

- 排行、分组、增长以及日内时段、星期、逐日变化在本地聚合。时段问题一次同时比较全部所选作品的多个指标，不再靠头部作品的历史分页拼凑全库分布。
- 时段使用相邻观测的指标增量，保留负变化；新作品初始总量不算作新增。零增长和缺测分开；间隔过长或压缩粒度太粗的记录不参与小时峰谷判断，并提示更合适的时间粒度。采样结束时段归属是近似，不代表事件真实发生时刻；比较时同时查看覆盖天数和作品小时归一化速率。
- 相同结构的多行结果采用列名加行值的无损编码，保留数字精度、空值、限制说明及分页；完整原始结果仍在来源与导出中。
- 重复查询引用同一份原始证据，包括首次概览；不会反复发送大结果，也不会产生多层引用链。
- 每次每篇约 3,000 个 Unicode 字符，按需补读未读位置。选更多篇不会挤占其他篇的片段长度；请求遵守网站间隔与冷却。
- 模型在阶段结束后用 `record_reading_notes` 整理统计或正文的来源、关键数字、观察、假设和待解决问题，将旧证据替换为笔记。笔记在工作上下文中只保存一份，不重复回显。工作集增大时额外提示整理，但不会阻止下一次读取。
- `retrieve_evidence` 可按字符位置回查本问任意原始来源，包括已释放的正文，无需重新访问网站。笔记是模型解释；精确引用必须核对原始证据。

界面从发送起显示正在分析的方向。公开反馈围绕用户的问题说明正在核对什么、已发现什么、接下来如何判断；只在有实质进展时更新，不再为每次工具完成自动生成流水账。调用名、缓存复用、来源原文、请求数及 token 用量收进默认折叠的“执行详情”。收起详情不影响公开反馈和最终回答；保存、恢复和 Markdown 导出保留有意义的反馈。流式刷新继续合并高频更新，不展示模型私有推理。公开说明的质量仍取决于所选模型遵循任务和证据，应用不会伪造阶段结论。

每次进入 Agent（包括首次打开、切回和刷新）默认显示新对话。历史记录需主动点击查看；切回新对话不会停止后台分析。最多三个会话同时生成，停止按钮只影响选中会话；关闭标签页仍会中断该页请求。未发送的旧会话草稿随旧会话保留。

工具轮数 0 表示自动继续；连续重复查询没有新证据时结束，可随时手动停止。无响应超时从最近一次收到流式事件重新计时，持续有输出的长请求不再受应用总时长截断。

实际输入、输出和服务商缓存 token 仍用于用量展示，不参与拦截。字节压缩量不等同于 token 账单节省。服务商实际上下文容量、默认输出上限、账户额度及网站限制仍存在；本地优化不能无限扩展模型容量，也不保证不同任务都节省同样比例。失败和截断会保留已有内容并明确提示，不自动重试付费请求。

## 缓存、密钥与对话

- **证据缓存**：默认复用确定性的本地查询结果，按账号和数据指纹隔离。数据变化后失效，24 小时过期，最多 40 条 / 256 KB。这不是训练模型。
- **正文缓存**：按账号、作品和采样方式隔离，可按配置复用或重新读取。远端编辑需重新采样才会体现。
- **API key**：默认仅存当前标签页会话；勾选记住后，在扩展数据库中未加密保存。作品备份、CSV 与对话 Markdown 导出不包含 key。
- **对话记录**：保存在独立的本地数据库中，按 Pixiv 账号隔离。需要单独导出或删除；清空作品历史不会同时删除 Agent 对话。

发给模型服务的内容由该服务处理。分享作品数据和采样正文之前，请确认地址正确并了解服务的数据政策。

## 常见问题

**连接成功，但作品问题答不出来？** 检查是否开启数据分享、是否完成同步，再展开工具记录，确认实际查询范围。测试连接不使用作品数据，不能证明本地历史充足。

**正文分析只读到少量内容？** 检查采样深度、页面访问状态和模型是否继续补读。自动档每次少量读取，固定阅读深度仍按用户选择执行；修改配置后重新提问，不会补写已完成回答的证据。

**如何继续上一次对话？** 每次进入默认打开新对话，点击左侧历史记录即可继续。对话按账号保存在本机，可单独导出或删除；作品数据备份与对话导出是两套入口。

**想排查协议或参与开发？** 阅读 [Agent 构建与排错教程](./agent-building-tutorial.zh-CN.md)。确定性协议夹具只能验证调用链路，真实模型的回复质量需要另行验收。
