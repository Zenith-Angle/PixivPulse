# Agent 0.5.4 验收记录

日期：2026-09-07。

## 行为与实现

- Responses / Chat Completions 流式事件映射为真实阶段：等待响应、连接、模型处理问题、准备工具、工具读取、证据返回和正文输出。进度包含用时及最多 80 条过程记录，不保存或展示内部推理原文，不伪造进度百分比。
- 收到文本立即进入显示缓冲，40ms 内的尾批次有定时补刷新，不再等待下一块或最终完成。服务商若仅返回最终文本，应用无法凭空提供尚未收到的正文，但等待状态仍可见。
- 输入框禁止原生拖拽，用展开/收起按钮向上覆盖部分消息区域，底部操作栏位置固定；折叠恢复消息空间。
- 已授权的正文采样先检查片段缓存，再复用用户已打开的对应小说页。没有可用页面时，直接 GET 固定的 Pixiv 原文页面，不创建、不关闭、不刷新用户标签页。
- 直接请求使用当前登录态，拒绝重定向、未知地址、超大响应、歧义正文、标题不匹配及验证页面。只读明确的原文元数据或正文段落，缓存与发送的仍为有界采样，完整 HTML/正文仅在采样期间内存中存在。
- 请求按扩展域全局锁串行、间隔至少 5 秒；429 尊重 Retry-After 且至少暂停 15 分钟，401/403 暂停 1 小时，网络/解析错误至少暂停 1 分钟。暂停时间保存在扩展本地存储，刷新不会清除；已打开页面的无网络读取和已有缓存仍可使用。此机制不等于不会触发风控，不做真人伪装、验证码或权限绕过。

## 0.5.5 后续修正与验收

用户反馈 0.5.4 安装态读取失败：首个错误是页面登录/验证检测，随后模型把应用冷却误称为限流，并在两个共享底层的工具之间反复尝试。因此 0.5.4 直接读取未通过安装态验收。

0.5.5 移除对整份 HTML 的验证关键词扫描，仅用明确挑战表单或页面标题判断验证页；无可验证正文时仍拒绝读取。回归证明正常脚本和隐藏验证码组件不再导致误判，但尚不能确认用户实际页面就是这一情况。

读取首次失败后，本问关闭工具进入总结；同轮其他正文调用也被阻止，保留对应错误输出满足协议完整性。错误提示区分应用冷却和真实 HTTP 限流，并禁止模型建议通过新对话绕过限制。

展开及消息操作按钮改为 26×26 图标（粗指针 32×32）。浏览器测量确认按钮无可见长文本，主按钮正常/hover/active 文字对比度均至少 4.5:1、键盘 focus 轮廓存在；桌面和 390px 页面展开定位和流式显示回归通过。全量 63 文件 / 460 测试、TypeScript、构建通过。0.5.5 新直接读取仍待安装态确认，不以协议 fixture 冒充真实 Pixiv 成功。

## 0.5.7 正文链路替换与会话恢复

用户反馈 0.5.5/0.5.6 仍无法在初始 HTML 中提取正文；之前的关键词误判修正未解决实际读取问题。该解析错误不能证明作者未开放作品。

0.5.7 移除初始 HTML 提取分支。已打开作品页仍可复用 DOM；否则直接请求 `/ajax/novel/{id}`，从经过错误信封和作品 ID 校验的 `body.content` 做采样。只在本地内存暂存接口正文，向模型及缓存交付受预算约束的片段。使用同一个全局请求锁和冷却记录，不因更换实现清除限流/权限限制。参考客户端源码：[sj2tpgk/pixiv-novel](https://github.com/sj2tpgk/pixiv-novel/blob/main/pixiv-novel.py)，此网页接口不具有官方公开 API 的稳定性承诺。

本地协议测试验证 JSON 请求地址、GET、登录态携带、内容类型、错误信封、ID 不匹配、缺失正文、采样上限和接口来源标识 `pixiv-web-api`。独立无登录态的只读请求返回 403 后停止；未提取用户 Cookie、未伪装请求，也未绕过扩展页自动化限制。因此安装态正文成功仍需用户重新加载后确认，不能用模拟响应代替。

会话恢复按账号保存最后选中的对话 ID，并显式处理页面从隐藏到显示的转换。浏览器用两段不同更新时间、每段 80 段文字的历史验证：恢复最后选中的旧对话；切走返回滚到底部；空白新对话离开后恢复上一段；刷新后仍恢复该选择。测试通过，不仅检查存储字段。

全量 63 文件 / 460 测试、TypeScript、构建与安装产物校验通过。证据：本地 `output/agent-057-tests.log`、`output/agent-057-restore.json`。这些是本地验收产物，不作为发布所需用户数据。

## 0.5.8 更新后资源预加载失败

## 0.5.9 流式文本与折叠执行记录

验收日期：2026-09-08。

- 接收端回归先复现旧行为：收到 `output_text.done` 后新增文字仍未交付。修复后覆盖 delta、text/content/item done、completed 补齐与逐块去重，在连接未完成时已交付文本。
- 工具前的模型公开说明转入有界执行记录；最终回答、复制与后续上下文使用独立正文。不会显示 reasoning 原文。原有历史不改写，新记录保持可恢复。
- 执行记录位于回答上方：运行时展开，显示实际查询动作、采样作品标题、采样字符数和缓存复用；开始输出或完成后收起，用户可手动展开。按钮桌面 26×26，粗指针 32×32。
- 普通增量即时显示；服务端大块文字用约 600ms 有界缓冲分批显示，不凭空生成内容。完整收到的文本独立持久化，停止/异常保留文本，减少动态效果偏好下直接显示。历史 Markdown 通过 memo 避免随每个新片段重复解析。
- 64 个测试文件、466 项通过。最终显示路径微调后额外 13 项回归通过，TypeScript、生产构建、原安装目录构建、ZIP 与安装资源版本完整性校验通过。
- 全量验收跨过午夜时发现原有数字动画测试依赖“今日”有观测：改为明确的近 24 小时范围验证动画，未修改该功能产品逻辑。
- 真实 DeepSeek Responses + 明确标记的演示数据：2 次请求，约 2.83 秒首段文本，约 4.03 秒完成，133 个片段，最大 5 字符。本次输入 3,922 tokens；这些是单次观测，不保证复杂正文分析相同耗时。
- Chrome 生产构建验证：工具说明与答案分离、答案完成前逐段可见、自动收起/手动展开、刷新恢复、26×26 按钮和 390px 无横向溢出。整块 completed 事件测试也出现多次递增可见长度，未在最后一次性出现。最终构建重新运行通过，未捕获错误为 0。
- 用户提供的多篇正文问题用于界面协议验收；逐篇读取标题和缓存复用另由生产 runner + 受控正文响应回归覆盖。未将用户作品写入默认提示词，未把协议夹具或演示数据测试声称为该问题在用户安装态的真实阅读验收。

本地证据：`output/agent-059-tests.log`、`output/agent-059-browser.json`、`output/agent-059-live-stream.json` 和 `output/playwright/agent-059-*.png`。本次不重新验证 Pixiv 传输层，使用者需要重新加载扩展并刷新看板获得 0.5.9。
## 0.5.10 通用对话进展、多篇采样与宽松配置

验收日期：2026-09-08。

- 公开进展说明、实际工具操作、最终回答分别展示和保存。自然语言说明位于操作之间，工具为默认折叠的独立条目；读取队列和证据保留在操作详情。完成后收起整个过程，仍可重新展开，复制与后续历史仅使用回答正文。
- Responses 和 Chat Completions 支持 `report_progress` 参数增量，解码未完成的 JSON 字符串、转义及 Unicode 分片，不展示私有推理。该通道不是必须调用的固定步骤，简单问题可以直接回答。
- 真实模型可能仍以普通文本发送进展。普通文本保持实时可见，待实际工具调用确认后归入过程；没有工具调用则保留为最终回答。不能提前根据文字增量判断它是最终回答，否则会导致过程反复折叠。兼容路径不要求固定话术，也不绑定采样问题。
- 回归先复现 8 篇请求被拒绝，实际正文调用为 0；同步移除选样 4 篇、单批 3 篇和每问 3 篇次上限后，8 篇全部进入读取。自动阅读按实际上下文分配，不再强制 6,000 字、70% 原文或正文证据比例；自定义支持 100% 覆盖，短篇可能覆盖全文，必须报告实际范围。
- 新配置默认自动阅读，单次输入、累计输入、工具轮数的 0 表示不设额外上限。已有配置保留，一键宽松设置只改这四项，不清除连接和密钥。模型上下文、输出预留、合法整数、网站权限与冷却继续有效。连续无新证据时关闭工具总结，避免空转。
- 每篇队列实时显示排队、请求间隔、读取、字符数、覆盖率、缓存、失败和跳过。中断及刷新保留已完成项，将未完成操作标记中断，不冒充成功。
- 全量 65 文件 / 480 测试通过，覆盖两种协议的增量到达、普通查询、直接回答、独立操作、复制隔离、历史恢复、中断和八篇读取。另以真实模型验证通用概念问答直接回答、数据充分性核对按需调用操作，均未触发正文读取。
